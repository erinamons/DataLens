一、项目当前状态

1. 项目定位
DataLens 是一个面向抖音/短视频内容的数据管理与分析工具，当前以本地桌面方式运行，通过 FastAPI 提供本地服务，再用 Edge app 模式或浏览器打开前端页面。

2. 技术栈
后端：Python + FastAPI
数据库：SQLite
前端：单文件 HTML/CSS/JavaScript
图表：Chart.js CDN
主要前端文件：D:\workbuddy\douyin-data\web\index.html
主要后端文件：D:\workbuddy\douyin-data\server.py
主要数据库文件：D:\workbuddy\douyin-data\database.py
配置文件：D:\workbuddy\douyin-data\config.py
服务端口：8900

3. 当前已实现功能
视频数据录入：标题、播放量、点赞数、评论数、分享数、发布日期、素材方向标签。
视频管理：列表、搜索、日期筛选、标签筛选、排序、分页、编辑、删除、批量打标签、批量删除。
文件能力：视频上传、视频播放、封面上传、CSV 导入导出。
分析页：素材方向统计、平均播放、平均互动率、趋势图、方向排名、数据洞察。
计划页：每日计划 CRUD、完成状态、优先级、日期切换、进度面板、筛选、TXT 导出。

4. 当前页面结构
顶部导航目前为三个标签：录入、分析、计划。
需要升级为四个主导航：工作台、视频库、分析、计划。
其中“录入”不再作为主页面名称，而应融入“视频库”的录入区或新增按钮中。

5. 用户明确要求
界面不要出现 emoji。
输出和方案尽量使用中文、纯文本、TXT。
设计风格要比当前更专业、更干净、更高级。
功能不要只停留在录入表格，要更像一个内容运营工作台。


二、升级总目标

本次升级的目标不是简单美化，而是把 DataLens 从“数据录入表格工具”升级为“内容运营决策工作台”。

目标效果：
1. 打开应用后先看到工作台首页，能快速知道今天要做什么、数据表现怎么样、哪些内容值得复盘。
2. 视频库从“录入页”升级为“素材资产管理页”，支持更舒服的录入、筛选、浏览和批量操作。
3. 分析页从“几个图表”升级为“结论优先”的分析页面，先给运营建议，再给图表。
4. 计划页从“待办列表”升级为“日程时间线”，更适合一天内容工作的安排。
5. 全局视觉统一，浅色、干净、专业，不能出现 emoji，使用文字、线性 SVG、CSS 图形代替。


三、设计规范

1. 禁止项
禁止使用 emoji。
禁止使用花哨霓虹风。
禁止使用过度饱和的紫蓝渐变。
禁止在管理后台中使用过于娱乐化的字体和装饰。
禁止使用纯黑大面积背景。
禁止为了炫技牺牲可读性。

2. 推荐视觉方向
整体风格：浅色专业、干净、轻量、高级。
背景色：#f6f7fb 或 #f8fafc。
主文字：#111827。
次级文字：#64748b。
边框色：#e5e7eb 或 #e2e8f0。
卡片背景：#ffffff。
主强调色：沿用当前 #e94560，但降低使用面积，只用于按钮、激活态、重点数字。
辅助色：
成功：#16a34a
警告：#f59e0b
信息：#2563eb
危险：#dc2626

3. 字体与间距
字体继续使用系统字体：-apple-system, BlinkMacSystemFont, "Microsoft YaHei", sans-serif。
页面最大宽度建议 1440px。
容器左右 padding 建议 24px 到 32px。
卡片圆角建议 16px 到 24px。
卡片阴影建议轻量：0 10px 30px rgba(15, 23, 42, 0.06)。
卡片边框建议：1px solid rgba(226, 232, 240, 0.8)。

4. 交互规范
按钮需要 hover、active、disabled 状态。
表单需要 focus 状态。
数据加载时不能空白，应显示 loading skeleton 或轻量加载态。
无数据时必须有空状态，不用 emoji，用 SVG 线性图标或 CSS 图形。
危险操作必须确认，例如删除视频、批量删除、删除标签。

5. 图标规范
不使用 emoji。
可以使用内联 SVG。
可以使用纯文字按钮。
可以使用 CSS 绘制的简单形状，如圆点、线条、进度条、状态标记。
当前已有的 +、×、X、↓、↑ 可以保留，但建议统一为 SVG 或文字。

3. get_dashboard_summary 查询逻辑

today 使用 Python date.today().isoformat()。

总视频数：
SELECT COUNT(*) FROM videos

总播放量：
SELECT COALESCE(SUM(play_count), 0) FROM videos

平均播放量：
SELECT ROUND(AVG(play_count), 0) FROM videos
如果没有数据，返回 0。

平均互动率：
公式：
CASE WHEN play_count > 0 THEN (like_count + comment_count + share_count) * 100.0 / play_count ELSE 0 END
然后取 AVG，保留两位。

标签数量：
SELECT COUNT(*) FROM tags

今日计划：
SELECT COUNT(*) total,
       SUM(CASE WHEN done=1 THEN 1 ELSE 0 END) done,
       SUM(CASE WHEN done=0 THEN 1 ELSE 0 END) pending,
       SUM(CASE WHEN done=0 AND priority='高' THEN 1 ELSE 0 END) high_pending
FROM plans
WHERE plan_date=?

最佳方向：
可以复用 get_tag_analysis() 的结果，取 avg_play 最高的标签。
注意 get_tag_analysis 已包含“未分类”。

Top 视频：
复用 get_top_videos(5, "play_count")。

最近视频：
SELECT v.*, interaction_rate FROM videos v ORDER BY created_at DESC LIMIT 5
并附带 tags。
如果不想重复写 tag 查询，可后续抽公共函数。

待办计划：
SELECT * FROM plans WHERE plan_date=? AND done=0 ORDER BY priority 排序, time_from, id LIMIT 6
优先级排序建议：高、中、低。
SQLite 可用 CASE：
ORDER BY CASE priority WHEN '高' THEN 1 WHEN '中' THEN 2 ELSE 3 END, time_from, id

insights 自动生成逻辑：
如果没有视频：提示“先录入视频数据，工作台会自动生成内容洞察。”
如果有高优先待办：提示“今天还有 X 个高优先任务未完成，建议先处理。”
如果最佳方向存在：提示“当前表现最好的方向是 XXX，平均播放 XXX。”
如果平均互动率低于 2：提示“整体互动率偏低，可以优化标题、封面和互动引导。”
如果最近视频为空：不显示该项。
